TOKENS & PRICING

Tokens & the Price You Can’t See

“The billing model assigns five token classes separate prices, and the highest-priced reasoning tokens do not appear in the visible response.”

A token count on its own does not determine cost. The meter charges according to which of several priced classes a token falls into, the surface it is billed through, and a set of deployment choices made before any token is spent.

Three billing surfaces and their units

Enterprise AI spend today runs through three metered surfaces a large organization typically uses at once: GitHub Copilot (billed in AI Credits, 1 credit = $0.01), Microsoft Foundry’s Azure OpenAI models (billed in USD per million tokens), and Microsoft Foundry’s Claude models (billed in Claude Consumption Units, 100 CCU = $1.00). All three ultimately resolve to the same underlying commodity (a priced token). The credit and CCU wrappers support marketplace invoicing but do not add economic information, and the three units are not reconciled automatically. A cost model must therefore distinguish the billing surfaces before it accounts for token class.

Token classes and their prices

Each model call bills across up to five token types (input, reasoning, output, cache-write, cache-read), each priced independently and priced differently again by model tier. Two patterns hold across the catalogue: cached input prices consistently around 0.1× base input on every vendor except Grok (0.25×), and cache write prices around 1.25× base input on the newest model families only, since older models carry no cache-write charge. Long-context tiering, which roughly doubles the input rate above a 200K–272K token threshold, applies to GPT, Gemini and Grok models and not to Anthropic’s.

REASONING-TOKEN COSTS

Reasoning tokens (chain-of-thought / extended-thinking content) are billed at the full output rate and never appear in the visible response. For most teams this is the largest unobserved cost, and its price changes over the token’s life: on current-generation Claude models a reasoning token bills as output when generated, as ordinary input on every later turn it survives in context, and at the cache-read rate if it is read back from cache. One semantic token can therefore carry up to four different prices, set by model choice and harness design rather than by anything the user did.

The cost formula

Cost is a sum across all five token classes and every model tier used in a pipeline, which token count × one price omits. A single call carries five moving cost parts, and an agentic task can make 10–200+ calls, each repeating that pattern. A cost model has to formalize this decomposition first, and a vendor’s single "total spend" line hides the detail that optimization requires.

GO DEEPER — cache-pricing regimes in Microsoft Foundry

Claude on Microsoft Foundry prices cache writes by retention duration: 1.25× base input for a 5-minute write, 2× for a 1-hour write. Azure OpenAI charges the same cache-write price regardless of retention, with retention set as a separate deployment parameter. A FinOps model that assumes one cache economics across a mixed Foundry estate will misprice half of it. Retention carries a price because a longer hold is rent on scarce accelerator memory; the underlying operation and the compute it consumes are identical for both durations.

The multipliers follow the physical resource each operation consumes. Prefill (processing a prompt) runs the accelerator near peak because every token is available at once, whereas decode (generating one token at a time) is memory-bandwidth bound by roughly two orders of magnitude, because each token requires streaming the whole model’s weights out of memory again. That asymmetry accounts for output prices of around 5× input, with continuous batching limiting the ratio by allowing many sequences to share one pass over the weights. It also accounts for a cache read, which skips prefill, being priced well below a fresh input token.

PRICING DATE AND SCOPE

Every figure above was checked against Microsoft, GitHub and Anthropic documentation as of 27 August 2026. Pricing increases for EU Data Zone and non-US regional deployments take effect 1 September 2026. Treat every rate, multiplier and threshold here as directional rather than as a quoted price, and verify current figures in the Azure pricing calculator before relying on them.

The three surfaces where spend occurs (Copilot, Azure OpenAI and Claude on Foundry) also record it. Their billing and usage telemetry makes per-task-class cost accounting possible and supports the downstream accountability and governance controls covered on the Agentic Loop page and closed out on the final page.
